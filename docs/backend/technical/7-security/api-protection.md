# 安全规范 - 接口防护

---

## 1. 限流规则

### 1.1 限流维度

| 维度 | 说明 |
|------|------|
| IP | 按请求 IP 限流 |
| 用户 | 按用户 ID 限流 |
| 接口 | 按接口路径限流 |

### 1.2 限流配置

| 接口 | 限制 | 时间窗口 |
|------|------|----------|
| 发送验证码 | 3 次 | 60 秒 |
| 验证登录 | 10 次 | 60 秒 |
| 通用 API | 100 次 | 60 秒 |
| 兑换码生成 | 100 次 | 60 秒 |

### 1.3 限流响应

**HTTP 状态码**: 429 Too Many Requests

```json
{
  "code": 42900,
  "message": "Rate limit exceeded",
  "data": null
}
```

## 2. CSRF 防护

### 2.1 CSRF 配置

| 环境 | CSRF 策略 |
|------|------------|
| API (前后端分离) | 禁用 |
| 管理后台 | 启用 |

### 2.2 禁用 CSRF 的条件

- 使用 JWT Token 认证
- 请求头携带 Token
- 非浏览器客户端

---

## 3. 输入校验

### 3.1 校验层级

| 层级 | 说明 |
|------|------|
| 前端校验 | 提升用户体验 |
| 后端校验 | 必须，安全保障 |
| 数据库校验 | 最后防线 |

### 3.2 常用校验注解

| 注解 | 用途 |
|------|------|
| @NotNull | 非空 |
| @NotBlank | 非空字符串 |
| @Email | 邮箱格式 |
| @Size | 字符串长度 |
| @Min/@Max | 数值范围 |
| @Pattern | 正则表达式 |

---

## 4. SQL 注入防护

### 4.1 防护措施

| 措施 | 说明 |
|------|------|
| 参数化查询 | 使用 JPA ParameterizedQuery |
| 输入校验 | 限制特殊字符 |
| 最小权限 | 数据库账户最小必要权限 |

### 4.2 JPA 正确用法

```java
// 正确
query.setParameter("email", email);

// 错误 - 字符串拼接
query.setQuery("SELECT u FROM User u WHERE u.email = '" + email + "'");
```

## 5. XSS 防护

### 5.1 防护措施

| 措施 | 说明 |
|------|------|
| HTML 转义 | 用户输入在页面展示时转义 |
| 输入校验 | 限制可输入字符 |
| Content-Type | 设置正确的 Content-Type |

### 5.2 响应头

```yaml
X-Content-Type-Options: nosniff
X-XSS-Protection: 1; mode=block
```

## 6. 敏感数据处理

### 6.1 敏感数据清单

| 数据 | 处理方式 |
|------|----------|
| 用户密码 | BCrypt 加密（若存储） |
| API Key | 环境变量，不存入代码 |
| 数据库密码 | 环境变量 |
| Token | HttpOnly Cookie |
| 用户手机号 | 脱敏展示 |

### 6.2 日志脱敏

| 数据 | 脱敏方式 |
|------|----------|
| 邮箱 | `u***@example.com` |
| 手机号 | `138****5678` |
| Token | 只记录前缀和后缀 |

---

## 7. 约束

| 约束 | 说明 |
|------|------|
| 限流必配 | 验证码发送接口必须限流 |
| 输入校验 | 所有用户输入必须校验 |
| 日志脱敏 | 敏感数据在日志中脱敏 |
| 错误消息 | 不返回技术细节给用户 |
